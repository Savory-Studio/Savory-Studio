## GET /api/promociones/activas

### Description

Retrieves the catalog of currently active promotions (`discount_status = 'Active'`) that are within their validity dates (`start_timestamp <= NOW() < end_timestamp`) and have remaining usage capacity (`USED count < max_uses`).

### Success Response

**HTTP 200 OK**

```json
[
  {
    "discountId": 5,
    "restaurantId": 1,
    "restaurantName": "Savory Grill",
    "name": "Lunch 20% off",
    "applicableProducts": "Executive menu",
    "type": "PERCENTAGE",
    "amount": 20.00,
    "customerTakesAmount": null,
    "customerPaysAmount": null,
    "status": "Active",
    "startTimestamp": "2026-10-26T08:00:00",
    "endTimestamp": "2026-11-26T23:59:00",
    "maxUses": 100,
    "maxUseAmountPerUser": 2,
    "imageUrl": "https://example.com/promo.jpg",
    "additionalUseConditions": "Valid Monday through Friday"
  }
]
```

## POST /api/promociones

### Description

Allows a restaurant owner to publish a new promotion (discount) by
providing the offer details, conditions, limits, and expiration. This
is the creation endpoint for the promotions lifecycle (RF-01).

### Request Body

```json
{
  "restaurantId": 1,
  "name": "Almuerzo 20% off",
  "applicableProducts": "Todos los platos del menú ejecutivo",
  "type": "PERCENTAGE",
  "amount": 20.00,
  "customerTakesAmount": null,
  "customerPaysAmount": null,
  "startTimestamp": "2026-10-26T08:00:00",
  "endTimestamp": "2026-11-26T23:59:00",
  "maxUses": 100,
  "maxUseAmountPerUser": 2,
  "imageUrl": "https://example.com/promo.jpg",
  "additionalUseConditions": "Válido solo para almuerzo"
}
```

**Fields NOT accepted in the request (set by the server):**
- `discount_id` — auto-generated by the database
- `discount_view_amount` — initialized to `0`
- `discount_status` — forced to `Active` on creation

### Field Constraints

| Field | Type | Required | Constraints |
|-------|------|----------|-------------|
| `restaurantId` | Integer | Yes | Must reference an existing restaurant |
| `name` | String | Yes | Non-blank |
| `applicableProducts` | String | Yes | Non-blank |
| `type` | String (enum) | Yes | One of: `PERCENTAGE`, `FIXED_VALUE`, `IXJ` |
| `amount` | BigDecimal | Conditional | Required when `type` is `PERCENTAGE` or `FIXED_VALUE`. For `PERCENTAGE`: must satisfy `0 < amount <= 100`. For `FIXED_VALUE`: must satisfy `amount > 0`. Ignored when `type` is `IXJ`. |
| `customerTakesAmount` | Integer | Conditional | Required when `type` is `IXJ`. Must satisfy `customerTakesAmount > customerPaysAmount` (RN-08). |
| `customerPaysAmount` | Integer | Conditional | Required when `type` is `IXJ`. Must be `> 0`. |
| `startTimestamp` | DateTime | No | If provided, must be before `endTimestamp` (when both present) |
| `endTimestamp` | DateTime | Conditional | See RN-09 — at least one of `endTimestamp` or `maxUses` must be provided |
| `maxUses` | Integer | Conditional | See RN-09 — at least one of `endTimestamp` or `maxUses` must be provided. Must be `> 0` if present. |
| `maxUseAmountPerUser` | Integer | No | Must be `> 0` if present |
| `imageUrl` | String | No | — |
| `additionalUseConditions` | String | No | — |

### Success Response

**HTTP 201 Created**

```json
{
  "discountId": 6,
  "restaurantId": 1,
  "name": "Almuerzo 20% off",
  "type": "PERCENTAGE",
  "amount": 20.00,
  "status": "Active",
  "startTimestamp": "2026-10-26T08:00:00",
  "endTimestamp": "2026-11-26T23:59:00",
  "maxUses": 100,
  "message": "Promoción creada exitosamente."
}
```

Side effects on success:
- A new row is inserted in the `discounts` table
- `discount_status` is set to `Active`
- `discount_view_amount` is initialized to `0`

### Authorization

Protected — requires `Authorization: Bearer <token>` header containing a valid signed HS256 JWT token issued by `POST /api/auth/login` (or `TEST_AUTH_TOKEN` with `X-User-Id` in local test environments).

- **Allowed callers (`REST-05`):** The restaurant owner (`restaurants.restaurant_owner_id`) OR an employee currently linked to that restaurant in `restaurant_staff`.
- **Cross-restaurant isolation:** Owners and staff of other restaurants receive `403 Forbidden`. Unlinking an employee via `DELETE /api/restaurants/{restaurantId}/staff/{userId}` revokes promotion publishing permission immediately.

### Business Rules

| Rule  | Description |
|-------|-------------|
| RN-06 | For `PERCENTAGE` type: discount amount must be greater than 0 and at most 100. For `FIXED_VALUE`: must be greater than 0. |
| RN-07 | `discount_status` is always set to `Active` on creation — callers cannot override it. |
| RN-08 | For `IXJ` type: `customerTakesAmount` must be strictly greater than `customerPaysAmount`. |
| RN-09 | A promotion must have at least one bound: `endTimestamp` or `maxUses` (or both). Both cannot be null simultaneously. |

### Data Model Dependencies

This contract operates on:
- `discounts` (all columns — this is the target table for insertion, active catalog queries, and automatic `Finished` lifecycle closure)
- `restaurants` (restaurant_id — validated via `restaurantId` in request)
- `coupon` (`coupon_id`, `discount_id`, `coupon_status` — counted as `USED` for exhaustion checks; never mutated during promotion closure)

## Automatic Promotion Closure (`APG-66` — `RF-04`)

### PO-01 Functional Equivalence & Enum Policy

- Functional references to `"Inactiva"` in business documentation map directly to the existing PostgreSQL `discount_status_enum` value **`Finished`** (`DiscountStatus.Finished`).
- No additional enum value is created in `discount_status_enum`; the existing database constraint (`Active`, `Suspended`, `Finished`) is preserved.
- **`Suspended` preservation rule:** Only promotions currently in **`Active`** transition automatically to **`Finished`**. Promotions in `Suspended` (manually paused by the restaurant) keep their `Suspended` status.

### Closure Triggers

| Trigger | Component | Condition | Behavior |
|---------|-----------|-----------|----------|
| **Periodic background sweep** | `PromotionLifecycleScheduler` → `PromotionLifecycleService` (interval `app.promotion-lifecycle.close-interval-ms`, default `60000` ms) | `discount_status = 'Active'` and (`discount_end_timestamp < CURRENT_TIMESTAMP` or `USED` count ≥ `discount_max_uses`) | Runs without requiring HTTP traffic; updates qualifying rows from `Active` to `Finished`. |
| **Immediate closure on last redemption** | `CanjeService.redeem` (`POST /api/canjes`) | `discount_status = 'Active'`, `discount_max_uses IS NOT NULL`, and new `USED` count equals `discount_max_uses` | Inside the same `@Transactional` `PESSIMISTIC_WRITE`-locked transaction after saving the coupon as `USED`, transitions the promotion to `Finished`. |

### Guarantees & Non-Destructive History

- **Coupon history preserved:** Closing a promotion updates only `discounts.discount_status` (`Active` → `Finished`). Existing `coupon` rows (`UNUSED` and `USED`), timestamps, and `coupon_hash` values are untouched so customer history (`GET /api/cupones/usuario/{userId}`) remains complete.
- **`UNUSED` claims do not exhaust `max_uses`:** Only redeemed (`USED`) coupons count toward capacity.
- **No subsequent redemptions accepted:** Any redemption attempt after automatic closure is rejected with `409 Conflict` (`RN-02` / `RN-05`) and leaves the database unmodified.

### SQL Evidence (`DiscountRepository`)

1. **Expired `Active` promotions closure (`finishExpiredPromotions`):**
   ```sql
   UPDATE discounts
   SET discount_status = CAST('Finished' AS discount_status_enum)
   WHERE discount_status = CAST('Active' AS discount_status_enum)
     AND discount_end_timestamp IS NOT NULL
     AND discount_end_timestamp < CURRENT_TIMESTAMP;
   ```

2. **Quota-exhausted `Active` promotions closure (`finishExhaustedPromotions`):**
   ```sql
   UPDATE discounts d
   SET discount_status = CAST('Finished' AS discount_status_enum)
   WHERE d.discount_status = CAST('Active' AS discount_status_enum)
     AND d.discount_max_uses IS NOT NULL
     AND (
         SELECT COUNT(*)
         FROM coupon c
         WHERE c.discount_id = d.discount_id
           AND c.coupon_status = CAST('USED' AS coupon_status_enum)
     ) >= d.discount_max_uses;
   ```
