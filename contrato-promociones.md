# REST Contract — Promotion Publishing

**Jira Subtask:** [BE] APG-XX
**Traceability:** RF-01 · RN-06 · RN-07 · RN-08 · RN-09

---

## POST /api/promociones

### Description

Allows a restaurant owner to publish a new promotion (discount) by
providing the offer details, conditions, limits, and expiration. This
is the creation endpoint for the promotions lifecycle (RF-01).

### Request Body

```json
{
  "restaurantId": 1,
  "name": "Almuerzo 20% off",
  "applicableProducts": "Todos los platos del menú ejecutivo",
  "type": "PERCENTAGE",
  "amount": 20.00,
  "customerTakesAmount": null,
  "customerPaysAmount": null,
  "startTimestamp": "2026-10-26T08:00:00",
  "endTimestamp": "2026-11-26T23:59:00",
  "maxUses": 100,
  "maxUseAmountPerUser": 2,
  "imageUrl": "https://example.com/promo.jpg",
  "additionalUseConditions": "Válido solo para almuerzo"
}
```

**Fields NOT accepted in the request (set by the server):**
- `discount_id` — auto-generated by the database
- `discount_view_amount` — initialized to `0`
- `discount_status` — forced to `Active` on creation

### Field Constraints

| Field | Type | Required | Constraints |
|-------|------|----------|-------------|
| `restaurantId` | Integer | Yes | Must reference an existing restaurant |
| `name` | String | Yes | Non-blank |
| `applicableProducts` | String | Yes | Non-blank |
| `type` | String (enum) | Yes | One of: `PERCENTAGE`, `FIXED_VALUE`, `IXJ` |
| `amount` | BigDecimal | Conditional | Required when `type` is `PERCENTAGE` or `FIXED_VALUE`. For `PERCENTAGE`: must satisfy `0 < amount <= 100`. For `FIXED_VALUE`: must satisfy `amount > 0`. Ignored when `type` is `IXJ`. |
| `customerTakesAmount` | Integer | Conditional | Required when `type` is `IXJ`. Must satisfy `customerTakesAmount > customerPaysAmount` (RN-08). |
| `customerPaysAmount` | Integer | Conditional | Required when `type` is `IXJ`. Must be `> 0`. |
| `startTimestamp` | DateTime | No | If provided, must be before `endTimestamp` (when both present) |
| `endTimestamp` | DateTime | Conditional | See RN-09 — at least one of `endTimestamp` or `maxUses` must be provided |
| `maxUses` | Integer | Conditional | See RN-09 — at least one of `endTimestamp` or `maxUses` must be provided. Must be `> 0` if present. |
| `maxUseAmountPerUser` | Integer | No | Must be `> 0` if present |
| `imageUrl` | String | No | — |
| `additionalUseConditions` | String | No | — |

### Success Response

**HTTP 201 Created**

```json
{
  "discountId": 6,
  "restaurantId": 1,
  "name": "Almuerzo 20% off",
  "type": "PERCENTAGE",
  "amount": 20.00,
  "status": "Active",
  "startTimestamp": "2026-10-26T08:00:00",
  "endTimestamp": "2026-11-26T23:59:00",
  "maxUses": 100,
  "message": "Promoción creada exitosamente."
}
```

Side effects on success:
- A new row is inserted in the `discounts` table
- `discount_status` is set to `Active`
- `discount_view_amount` is initialized to `0`

### Error Responses

| Code | Scenario | Message | Rule |
|------|----------|---------|------|
| 400  | Required field missing or blank | "El campo {field} es obligatorio." | — |
| 400  | `type` is not a valid enum value | "El tipo de descuento no es válido. Valores permitidos: PERCENTAGE, FIXED_VALUE, IXJ." | — |
| 400  | `amount` missing when `type` is `PERCENTAGE` or `FIXED_VALUE` | "El campo amount es obligatorio para descuentos de tipo {type}." | — |
| 400  | `amount` out of range for `PERCENTAGE` (not in `(0, 100]`) | "El porcentaje debe ser mayor a 0 y menor o igual a 100." | RN-06 |
| 400  | `amount` ≤ 0 for `FIXED_VALUE` | "El monto del descuento debe ser mayor a 0." | RN-06 |
| 400  | `customerTakesAmount` or `customerPaysAmount` missing for `IXJ` | "Los campos customerTakesAmount y customerPaysAmount son obligatorios para tipo IXJ." | — |
| 400  | `customerTakesAmount` ≤ `customerPaysAmount` for `IXJ` | "La cantidad que lleva el cliente debe ser mayor a la que paga." | RN-08 |
| 400  | Both `endTimestamp` and `maxUses` are null | "Debe especificar fecha de vencimiento o límite de usos (o ambos)." | RN-09 |
| 400  | `startTimestamp` ≥ `endTimestamp` | "La fecha de inicio debe ser anterior a la fecha de vencimiento." | — |
| 400  | Malformed JSON or unreadable body | "El cuerpo de la petición es inválido o está vacío." | — |
| 404  | `restaurantId` does not exist | "Restaurante no encontrado." | — |

### Authorization

Restaurant owner only — validated via JWT bearer token (implementation
deferred to the security sprint). During Sprint 1, the endpoint is open
for functional testing.

### Business Rules

| Rule  | Description |
|-------|-------------|
| RN-06 | For `PERCENTAGE` type: discount amount must be greater than 0 and at most 100. For `FIXED_VALUE`: must be greater than 0. |
| RN-07 | `discount_status` is always set to `Active` on creation — callers cannot override it. |
| RN-08 | For `IXJ` type: `customerTakesAmount` must be strictly greater than `customerPaysAmount`. |
| RN-09 | A promotion must have at least one bound: `endTimestamp` or `maxUses` (or both). Both cannot be null simultaneously. |

### Data Model Dependencies

This contract operates on:
- `discounts` (all columns — this is the target table for insertion)
- `restaurants` (restaurant_id — validated via `restaurantId` in request)
